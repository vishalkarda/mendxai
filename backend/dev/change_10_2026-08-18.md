## Purpose

Following `change_9`'s baseline model, the user asked for three concrete improvements plus a general-purpose logging utility: (1) early stopping for the neural net's CV loop (it was previously training a fixed 50 epochs per fold with no validation split, memorizing training data), (2) shifting model/threshold selection to prioritize recall over precision — this is a depression-screening context, where a false negative (missed case) is costlier than a false positive — and (3) a persistent, cross-run history of CV results, since nothing previously distinguished one run's numbers from another's. Plus: a uniform, singleton-pattern logger that all modules can write to, landing in one shared, timestamped log file per process run.

## Scope / Files Changed
- `backend/src/mendxai/core/logging_utils.py` (new) — singleton `get_logger()`/`get_log_path()`, one shared `logs_<datetime>.log` per process run plus console output, safe to call from any module any number of times
- `backend/src/mendxai/ml/trainer.py` — `cross_validate()` substantially rewritten: inner train/val split per fold (for NN early stopping + leak-free threshold tuning), F2-optimal threshold search, expanded per-fold metrics (f2, tuned_threshold, and `*_tuned` variants of every metric), per-fold model chatter suppressed via `contextlib.redirect_stdout`, key milestones routed through the new logger, new `_append_run_history()` writing to `backend/results/logs/run_history.csv`
- `backend/src/mendxai/ml/aggregation.py` — one `logger.info()` call added (validates the singleton works identically across modules)
- `backend/src/mendxai/ml/models/gradient_boosting_model.py` — added `min_samples_leaf` param (see Key Facts — this was a real bug fix, not just plumbing)
- `backend/src/mendxai/core/config.py` — added `cv_inner_val_size` (TrainingConfig) and `gb_min_samples_leaf` (ModelConfig)
- `backend/notebooks/05_baseline_model.ipynb` — updated for the new `cross_validate()` API; removed the notebook's own manual `contextlib.redirect_stdout` wrapping (now redundant — suppression happens inside `trainer.py`); neural net bumped to the same 100-fold scale as the other two models (previously 50, to limit output volume — no longer a concern); best-model selection switched from F1 to F2 (tuned threshold)

## Summary

`cross_validate()` now carves an inner train/validation split from each fold's training portion (never the held-out test fold), using it for two things: neural-net early stopping (previously absent — the NN was training a fixed 50 epochs and memorizing each fold), and tuning the classification threshold to maximize F2 (recall-weighted) rather than assuming 0.5. Both default- and tuned-threshold metrics are reported per fold so the effect of tuning is visible, not just asserted. A singleton logger (`mendxai.core.logging_utils`) now backs a shared, timestamped log file per run, and every `cross_validate()` call appends a summary row to `backend/results/logs/run_history.csv` for cross-run comparison. While implementing this, a real bug surfaced and was fixed: `HistGradientBoostingClassifier`'s default `min_samples_leaf=20` silently produced a constant, unsplit model once the inner-train fold shrank below ~40 samples — caught via an exactly-0.500 AUC, not a thrown error.

## Key Facts / Findings Recorded

- **Real bug: `HistGradientBoostingClassifier(min_samples_leaf=20)` (sklearn's default) cannot split with <40 training samples.** Once `cross_validate()`'s inner train/val split reduced a fold's inner-training set to ~32-33 samples, gradient_boosting silently trained a constant model: `predict_proba` returned exactly `[0.5, 0.5]` for every input, giving AUC exactly 0.500 and (with class balancing) recall exactly 1.0 by always predicting the positive class — no exception raised, no warning. Diagnosed by checking `np.unique(predict_proba(...))` directly. Fixed by adding `gb_min_samples_leaf: int = 10` to `config.py` and passing it through `GradientBoostingModel`. **Lesson for this dataset's scale: a clean training run with no errors is not evidence a model learned anything — check for degenerate/constant predictions explicitly whenever training-fold sizes are this small (well under sklearn's defaults' assumptions).**
- **Threshold tuning matters more than model choice at this sample size.** After the fix, tuning the decision threshold (vs. the default 0.5) moved gradient_boosting's recall from 0.559→0.725 (F2 0.559→0.672) and neural_net's from 0.576→0.689 (F2 0.586→0.652), while decision_tree barely moved (0.575→0.592). All three models had usable signal in `predict_proba` that the default 0.5 cutoff was leaving on the table.
- **Best model changed under the new (correct) selection criterion.** Selecting by F1 (as in `change_9`) picked neural_net. Selecting by F2 with tuned threshold (recall-weighted, appropriate for a screening context) picks **gradient_boosting**, recommended operating threshold ≈0.258 (mean across 100 folds; per-fold values have wide spread — treat as a starting point, not a precise number, given each fold's threshold is tuned on only ~32-40 samples).
- **Full final CV results** (5-fold × 20 repeats = 100 folds, all three models, default vs tuned threshold):

  | model | acc (0.5) | recall (0.5) | AUC | acc (tuned) | recall (tuned) | F2 (tuned) | tuned threshold |
  |---|---|---|---|---|---|---|---|
  | decision_tree | 0.622 | 0.575 | 0.621 | 0.624 | 0.592 | 0.575 | 0.084 |
  | gradient_boosting | 0.646 | 0.559 | 0.711 | 0.626 | 0.725 | 0.672 | 0.258 |
  | neural_net | 0.699 | 0.576 | 0.746 | 0.646 | 0.689 | 0.652 | 0.256 |

  Verified identically from both the notebook and `python main.py --stage train --level subject --model all` (independent runs, matching numbers to 3+ decimal places).
- The neural net's early-stopping fix means the `change_9` finding ("NN memorizes training data with no early stopping") is now resolved — its CV loop uses a real inner validation split for stopping, not just for threshold tuning.

## Migration / Deployment Steps
1. No action needed. `cross_validate()`'s signature is backward compatible (`tune_threshold=True` and `log_run_history=True` both default on; pass `False` to opt out of either).
2. Any code that previously called `cross_validate()` and consumed only the original columns (`accuracy`/`precision`/`recall`/`specificity`/`f1`/`auc_roc`) is unaffected — those columns are unchanged, just joined by new ones.

## Rollback Steps
1. `git revert` this change's commit(s). `logging_utils.py` is net-new and self-contained; `trainer.py`'s changes are additive to `cross_validate()`'s output shape (no removed columns); `gradient_boosting_model.py`'s `min_samples_leaf` fix should not be rolled back independently — it fixes a real correctness bug, not a style preference.
